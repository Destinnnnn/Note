## 4.8 虚拟存储器

### 4.8.1 相关概念和基本工作原理

- 虚拟存储器把主存和辅存构成一个统一的、可供 [[1.3 计算机硬件#1.3 计算机硬件|CPU]] 直接访问的超大容量主存。
- 程序员在运行程序时，面对的是虚拟存储器，相应使用的是==虚拟地址 `VA`==。
- [[4.1 存储器概述#4.1.3 主存的基本结构|主存]]中的实际地址称为==物理地址 `PA`==。
- 为实现虚拟存储器，需要软硬件配合：
	- 软件：[[1.4 计算机软件#1.4 计算机软件|操作系统]]。
	- 硬件：存储管理单元 `MMU`。
- CPU 通过 `MMU` 把虚拟地址转换为主存中的物理地址。
- 若数据块未调入主存，会发生缺失，由[[1.4 计算机软件#1.4 计算机软件|操作系统]]把缺失内容从辅存调入主存。
- 虚拟存储器不是主存和辅存的简单缓存，而是要解决数据块大小、地址映射、替换和写入等问题。

### 4.8.2 页式虚拟存储器

#### 4.8.2.1 概述

- 页式虚拟存储器把虚拟地址空间划分为大小固定的页面 `page`。
- 虚拟地址空间中的页称为==虚拟页 `Virtual Page`==。
- 主存与辅存之间以页面为单位交换信息。
- 页式虚拟存储器采用==请求分页==的思想：
	- 把进程中最近访问或即将访问的指令和数据从辅存调入主存。
	- 暂时不用的页面可不调入主存。
	- 当访问的页面不在主存中时，发生缺页，再由[[1.4 计算机软件#1.4 计算机软件|操作系统]]将缺失页面调入主存。
- 缺页处理代价远大于 [[4.7 高速缓冲存储器cache#4.7 高速缓冲存储器cache|cache]] 缺失处理代价，因此页面通常设置得比 cache 数据块大，图中给出常见页面大小为 `4KB`。
- 主存和辅存之间通常采用全相联映射方式，以提高命中率。

#### 4.8.2.2 地址映射和页表

- 页式虚拟存储器使用==页表==描述虚拟页到物理页的映射关系。
- 虚拟地址通常划分为：
	- 虚拟页号。
	- 页内偏移。
- 物理地址通常划分为：
	- 物理页号。
	- 页内偏移。
- 页内偏移在地址转换前后保持不变。
- 每个进程有一张常驻主存的页表。
- 页表基址寄存器 `PTBR` 用于记录该进程页表在主存中的首地址。

| 页表项字段     | 作用                                     |
| --------- | -------------------------------------- |
| 有效位       | 表示该虚拟页是否在主存中。                          |
| 脏位        | 表示该页是否被修改过。                            |
| 替换控制位     | 用于页面替换算法。                              |
| 访问权限位     | 控制读、写、执行等权限。                           |
| 禁止缓存位     | 控制该页是否可被 cache 缓存。                     |
| 存放位置/物理页号 | 有效位为 `1` 时给出物理页号；有效位为 `0` 时可记录在磁盘中的位置。 |

#### 4.8.2.3 访问流程

1. CPU 给出虚拟地址。
2. `MMU` 根据虚拟页号和 `PTBR` 生成页表项地址。
3. 访问主存中的页表项。
4. 若页表项有效位为 `1`，取出物理页号，与页内偏移拼接得到物理地址。
5. 通过物理地址访问主存中的目标数据。
6. 若页表项有效位为 `0`，说明页面不在主存中，发生缺页。
7. [[1.4 计算机软件#1.4 计算机软件|操作系统]]进行缺页异常处理，从辅存调入所需页面，并更新页表。

- 若调入页面时主存没有空闲页框，需要根据页面替换算法选择页面换出。
- 如果被换出的页面脏位为 `1`，需要写回辅存。

#### 4.8.2.4 使用快表TLB加速地址转换

- 为加快 `MMU` 的虚拟地址到物理地址转换过程，可以在 `MMU` 内部设置一个专门的高速缓存：==转换后备缓冲器 `[[4.8 虚拟存储器#4.8.2.4 使用快表TLB加速地址转换|TLB]]`==。
- `TLB` 用于缓存经常访问的页表项。
- `TLB` 可看作容量很小的 cache，只不过缓存对象是页表项。
- `TLB` 的访问速度远高于主存。
- 为提高查找速度，`TLB` 一般采用全相联或组相联方式。
- `TLB` 查找时：
	- 全相联方式：虚拟页号与所有项的标记并行比较。
	- 组相联方式：先用索引定位组，再与组内标记并行比较。
- 若 `TLB` 命中，可直接得到物理页号。
- 若 `TLB` 缺失，需要访问主存中的页表项，并在必要时更新 `TLB`。

#### 4.8.2.5 基于TLB、cache的访存流程

- 现代计算机一般都会采用虚拟存储器技术，虚拟存储器需要硬件 `MMU`、`TLB` 与操作系统协同工作。
- 基本流程：
	1. CPU 给出虚拟地址。
	2. 查询 `TLB` 中是否有对应页表项。
	3. 若 `TLB` 命中，将虚拟地址转换为物理地址。
	4. 根据物理地址访问 cache。
	5. 若 cache 命中，直接访问 cache 中的数据。
	6. 若 cache 缺失，进行 cache 缺失处理，从主存调入数据块。
	7. 若 `TLB` 缺失，则访问页表；若页表命中，更新 `TLB` 后继续访存。
	8. 若页表缺失，则发生缺页异常，由[[1.4 计算机软件#1.4 计算机软件|操作系统]]从辅存调入页面。
