## 4.7 高速缓冲存储器cache

### 4.7.1 cache的相关基本概念

- [[4.1 存储器概述#4.1.3 主存的基本结构|主存]]一般采用 `DRAM`，容量大、成本低，但速度较慢。
- `SRAM` 容量小、成本高，但速度快。
- 为提高 CPU 访问主存的性能，通常在 CPU 与主存之间加入一个 `SRAM` 作为==高速缓冲存储器 [[4.7 高速缓冲存储器cache#4.7 高速缓冲存储器cache|cache]]==。
- [[1.3 计算机硬件#1.3 计算机硬件|CPU]] 不再直接访问慢速主存，而是通过主存地址访问快速 cache。

#### 程序局部性

| 局部性 | 含义 |
| --- | --- |
| 时间局部性 | 某个存储位置在一段时间内被访问后，未来可能会被多次访问。 |
| 空间局部性 | 某个存储位置被访问后，与它相邻的存储位置也可能被访问。 |

- cache 利用程序局部性，把主存中的数据块复制到 cache 中。
- 主存和 cache 都划分成大小固定的数据块 `Block`，每个数据块包含若干字。
- 若访问的数据块不在 cache 中，就把主存中包含该数据的数据块调入 cache。

#### cache 性能评价

- 设某程序运行期间：
	- cache 命中次数为 `n_c`。
	- 主存访问次数为 `n_m`。
- 命中率：
	- `h = n_c / (n_c + n_m)`
- 缺失率：
	- `1 - h`
- 命中时访问时间记为 `t_c`，缺失时访问时间记为 `t_m`。
- cache/主存系统的平均访问时间：
	- `t_a = h t_c + (1 - h)t_m`
- 访问效率：
	- `e = t_c / t_a = 1 / (h + (1 - h)r)`
	- 其中 `r = t_m / t_c`。

### 4.7.2 cache的读、写流程

#### 读流程

1. CPU 发出主存地址 `addr`。
2. cache 根据地址判断数据是否命中。
3. 若命中，CPU 直接读取 cache 中的数据。
4. 若缺失，则为缺失数据分配 cache 数据块，必要时进行数据块替换。
5. 从主存读入包含目标数据的数据块，更新 cache。
6. CPU 读取 cache 中的数据。

- 强调：读 cache 命中时访问时间最短。
- 构建 cache 系统时，应尽量提高命中率。

#### 写流程

- 写操作先判断数据是否命中。
- 命中时：
	- 可以只写入 cache，然后按策略处理主存。
	- 也可以同时写入 cache 和主存。
- 缺失时：
	- 可以把对应主存块装入 cache 后再写。
	- 也可以只写入主存，不装入 cache。

### 4.7.3 地址映射

- 地址映射解决的问题：主存中的数据块放到 cache 的哪个位置。
- cache 行通常包含：
	- 有效位 `valid`。
	- 标记 `tag`。
	- 数据块副本。
- 系统启动或复位时，cache 有效位通常为 `0`。
- 当主存数据块调入 cache 后，有效位置 `1`，并保存相应标记。

#### 4.7.3.1 直接映射

- 直接映射规则：每个主存数据块只能映射到 cache 中的一个固定行。
- 映射公式：
	- `cache行号 = 主存数据块号 mod cache行数`
- 主存地址通常划分为：
	- 主存分区号 `tag`。
	- 区内数据块号 `index`。
	- 数据块内偏移 `offset`。
- 查找时用 `index` 找到 cache 行，再比较该行的 `valid` 和 `tag`。

| 优点 | 缺点 |
| --- | --- |
| 硬件简单，查找速度快。 | 冲突多，同一映射位置的数据块会互相替换。 |
![[Pasted image 20260701171724.png]]


#### 4.7.3.2 全相联映射

- 全相联映射规则：每个主存数据块都可以映射到 cache 中的任意一个 cache 行。
- 主存地址通常划分为：
	- 数据块地址 `tag`。
	- 块内偏移 `offset`。
- 查找时需要把主存数据块地址与 cache 中所有有效行的标记同时比较。
- 图中指出，可用内容可寻址存储器 `CAM` 实现并行比较。

| 优点 | 缺点 |
| --- | --- |
| 冲突少，cache 空间利用灵活。 | 硬件复杂，需要并行比较多个标记。 |
![[Pasted image 20260701171816.png]]


#### 4.7.3.3 组相联映射

- 组相联映射把 cache 行分成大小相同的若干组，每组包含若干行。
- 每个主存数据块按固定规则映射到某个 cache 组，在该组内可放入任意一行。
- 映射公式：
	- `cache组号 = 主存数据块号 mod cache组数`
- 主存地址通常划分为：
	- 主存分区号 `tag`。
	- 区内块号 `index`。
	- 块内偏移 `offset`。
- 查找时先用组索引定位 cache 组，再把 `tag` 与该组内各行的标记并行比较。

### 4.7.4 替换算法

- 当 cache 已满且发生缺失时，需要选择一个 cache 行进行替换。
- 直接映射中，每个主存块只对应一个固定 cache 行，因此不需要替换算法。
- 全相联和组相联中，需要使用替换算法。

| 替换算法 | 基本思想 |
| --- | --- |
| `FIFO` 先进先出 | 记录每个 cache 行装入主存块的时刻，优先替换最早进入 cache 的块。 |
| `LFU` 最不经常使用 | 记录每个 cache 行被访问次数，优先替换计数值最小的块。 |
| `LRU` 近期最少使用 | 记录近期访问情况，优先替换最近最少使用的块。 |
| 随机替换 | 随机选择一个可替换的 cache 行。 |

- `LRU` 的计数器位数与组内 cache 行数有关。
- `LRU` 体现近期访问局部性，但实现==需要维护状态信息，即LRU位==。

- 当某段时间集中访问的主存区域超过 cache 组大小时，命中率可能变得很低，甚至为 0。这种现象也称为==颠簸或抖动。==
### 4.7.5 写入策略

#### 写命中

| 策略 | 中的处理 |
| --- | --- |
| 写回法 `Write-Back` | 只把新数据写入 cache，不立即写入主存；当该 cache 行被替换时，若修改过，再写回主存。 |
| 写穿法 `Write-Through` | 写 cache 的同时，也把数据写入主存，使 cache 和主存保持一致。 |

- 写回法需要为每个 cache 行设置==脏位 `Dirty Bit`==。
	- `Dirty Bit = 1`：该行被修改过，替换时需要写回主存。
	- `Dirty Bit = 0`：该行未被修改，替换时可直接覆盖。
- 写回法可减少写主存次数，但存在 cache 与主存中数据暂时不一致的问题。
- 写穿法不需要脏位，能保持 cache 与主存一致，但写主存开销更大。
![[Pasted image 20260701172323.png]]
#### 写缺失

| 策略 | 中的处理 |
| --- | --- |
| 写分配法 `Write-Allocate` | 把缺失数据所在的主存块调入 cache，再在 cache 中完成写入。 |
| 非写分配法 `Not-Write-Allocate` | 只把新数据写入主存，不把该主存块调入 cache。 |

- 写分配法可利用空间局部性，但写入主存块会增加读主存开销。
- 非写分配法减少读主存开销，但没有利用空间局部性。

### 4.7.6 cache的分类和应用

| 分类 | 中的说明 |
| --- | --- |
| 统一 cache | 指令和数据都存放在同一个 cache 中。 |
| 分离 cache | 将 cache 分成数据 cache 和指令 cache，减少取指令与取数据之间的冲突。 |
| 多级 cache | 现代 CPU 常使用 L1、L2、L3 等多级 cache。 |
| 软件 cache | 由软件机制实现的缓存，如 `buffer cache`、`web cache`。 |

- 图中以 Intel Core i7 为例，展示了多级 cache：
	- 每个核心可有自己的 L1 数据 cache、L1 指令 cache。
	- L2 cache 可与核心对应。
	- L3 cache 可被多个核心共享。
- `buffer cache` 通常指[[1.4 计算机软件#1.4 计算机软件|操作系统]]或数据库系统中用于存储经常访问数据的一种缓存机制。
- `web cache` 用于缓存网络访问中的数据。
