## 3.4 定点数的除法运算

### 3.4.1 原码除法运算 — 恢复余数法
![[Pasted image 20260701164553.png]]
- [[2.3 定点数的编码#2.3.1 原码|原码]]除法可以把符号位和数值位分开处理。
- 商的符号：
	- 被除数符号位 `⊕` 除数符号位。
- 商的数值部分：
	- 用被除数和除数各自的数值部分相除得到。
- 余数的符号与被除数相同。
- 对定点小数除法，为了保证商也是定点小数并避免溢出，给出的条件是：`|X| < |Y|`。

#### 恢复余数法思路

- 每次先用当前余数减除数，得到中间余数。
- 若中间余数 `>= 0`：
	- 上商 `1`。
	- 中间余数左移一位，继续下一步。
- 若中间余数 `< 0`：
	- 上商 `0`。
	- 加回除数，恢复余数。
	- 恢复后的余数左移一位，继续下一步。

### 3.4.2 原码除法运算 — 不恢复余数法

- 不恢复余数法也称为==加减交替法==。
- 它是在恢复余数法基础上的改进：当中间余数为负时，不必先恢复余数再进行下一轮减法。
- 设通过过程中某次的余数为 `R_i`，相应上商位为 `Q_i`：

| 条件 | 上商 | 下一次余数 |
| --- | --- | --- |
| `R_i >= 0` | `Q_i = 1` | `R_{i+1} = 2R_i - Y` |
| `R_i < 0` | `Q_i = 0` | `R_{i+1} = 2R_i + Y` |

- 这样可以跳过“恢复余数”这一步，直接得到下一次中间余数。
- 硬件实现与恢复余数法相近，核心区别是根据余数符号决定下一步加除数还是减除数。
### 3.4.3 补码除法运算 — 不恢复余数法

- [[2.3 定点数的编码#2.3.2 补码|补码]]除法中，被除数、除数和中间余数都带有符号。
- 因此不能像[[2.3 定点数的编码#2.3.1 原码|原码]]除法那样把符号位单独处理，而要让符号位和数值部分一起参加运算。
- 判断“够减”的依据：
	- 中间余数与除数符号的关系。
	- 相应做减法或加法后结果的符号。

#### 初始处理

| 被除数与除数的符号关系 | 初始中间余数                    |
| ----------- | ------------------------- |
| 同号，商为正      | `[R_1]_补 = [X]_补 - [Y]_补` |
| 异号，商为负      | `[R_1]_补 = [X]_补 + [Y]_补` |
- 若商为正：
	- “够减”上商 `1`。
	- “不够减”上商 `0`。
- 若商为负：
	- “够减”上商 `0`。
	- “不够减”上商 `1`。

#### 后续余数

| 上商位 | 下一次余数 |
| --- | --- |
| `1` | `[R_{i+1}]_补 = 2[R_i]_补 + [-Y]_补` |
| `0` | `[R_{i+1}]_补 = 2[R_i]_补 + [Y]_补` |
- 商符号在求商过程中自然形成。
- 定点小数补码除法仍需要满足被除数绝对值小于除数绝对值，否则商会大于 `1` 而溢出。
- 末位商恒置 `1`。
