## 6.4 控制器
### 6.4.1 CPU的时序及其控制方式
- 早期计算机采用==三级时序==对操作控制信号进行定时控制
	- 状态周期：完成一个基本操作的时间单元
	- 节拍电位：由状态周期划分出的若干个操作阶段
	- 节拍脉冲：节拍电位内的同步信号，用于触发具体微操作

	定长指令周期的三级时序
	![[Pasted image 20260630180214.png]]
	**对于指令集中包含大量功能简单的指令而言，会造成时间浪费**

	变长指令周期的三级时序
	![[Pasted image 20260630180549.png]]

	**不要将定长指令周期和变长指令周期与定长[[5.1 指令系统概述#5.1 指令系统概述|指令系统]]和变长指令系统混淆了**

	- 以上两种对控制器产生控制信号进行时间控制的方式都属于==同步控制方式== 
		- 同步控制方式将各部件中==最长操作时间==作为标准时间间隔
		- 同步控制方式的时序关系比较简单，因此控制器的设计比较方便。若存在慢速部件则CPU效率较低
		- 根据==同步粒度==（状态周期数量、节拍电位数量是否可变）的不同，同步控制方式还可以进一步分类，例如以上介绍的定长指令周期和变长指令周期的三级时序
	- 异步控制方式
		- 没有统一的CPU时钟信号，也没有固定的状态周期和节拍电位
		- 控制器对各功能部件采用==应答机制==：必须等功能部件发回应答信号才能开始下一步的操作控制
		- 不存在快速部件等待慢速部件的情况。
		- 结构比较复杂
	- 联合控制方式
		- 将同步控制方式与异步控制方式结合
		-  大多数时间固定的操作采用同步控制
		- 少量时间难以确定的操作采用异步控制方式

### 6.4.5 微程序控制器
![[Pasted image 20260630222229.png]]
#### 6.4.5.1微程序控制器的相关基本概念
- 微程序控制器的核心思想
	- 模仿程序设计的方式。
	- 将指令集中每一条指令执行所需的相关控制信号按照某种规则==编码成微指令==。
	- 使用相关的微指令，为每一条指令编写相应的微程序以实现指令功能。==微程序由若干微指令构成==。
	- 将每一条指令的==微程序全部存放在一个只读存储器ROM==中，这种存储器位于CPU中，称为==控制存储器。==
	![[Pasted image 20260630212333.png]]
	- 相较于硬布线控制器采用硬件时序对控制信号进行定时控制，微程序控制器采用==软件时序==对控制信号进行定时控制，简化了复杂的控制逻辑，提高了设计的灵活性和可维护性。
- 微命令和微操作
	- 控制部件向执行部件发送的各种控制信号称为==微命令==
	- 执行部件收到微命令后执行相应的操作称为==微操作==

#### 6.4.5.2 微程序控制器的组成
![[Pasted image 20260630211000.png]]![[Pasted image 20260630211024.png]]

| 名称             | 含义                                                           |
| -------------- | ------------------------------------------------------------ |
| **地址转移逻辑**     | 用来产生“下一条微指令地址”的组合逻辑。它会根据当前机器指令、外部状态条件、判别测试字段、下址字段等，决定下一微地址。  |
| **微地址寄存器 μAR** | 保存当前要访问的微指令地址。它把地址送到控制存储器 CS，用来取出对应微指令。通常初始化为 0，从取指微程序开始。    |
| **控制存储器 CS**   | 专门存放微程序的存储器。里面每一个单元存一条微指令，多个微指令组成一段微程序，用来完成一条机器指令。           |
| **操作控制字段**     | 微指令中用来产生微操作控制信号的部分。例如控制 `PC -> MAR`、`MDR -> IR`、ALU运算、读写主存等。 |
| **判别测试字段**     | 指明要测试哪些条件。比如是否有中断、ALU 标志位、指令类型、外部状态 `FB1 ~ FBk` 等，用来决定是否转移。  |
| **下址字段**       | 给出下一条微指令的候选地址，通常作为微程序转移的目标地址。它会送入地址转移逻辑，参与形成最终的下一微地址。        |

#### 6.4.5.6 微指令中操作控制字段的表示方法
- 微指令的操作控制字段采用==直接表示法==，即每个二进制位定义为一个微命令位。
	- 取值为1表示需要产生相应的微操作控制信号。
	- 取值为0表示不需要产生相应的微操作控制信号。
- 编码表示法（字段译码法）
	![[Pasted image 20260630220606.png|661]]
	- **每个译码器的输出状态中（如3-8译码器有8个输出状态）需要预留一个状态，这个状态表示当前微指令不使用该译码器所对应字段所包含的互斥微命令中的任何一个。这样做的原因是： 并不是每一条微指令都会用到每个互斥微命令字段中的微命令。**

#### 6.4.5.7 水平型微指令和垂直型微指令
- 在一个微指令周期内都可以同时给出多个微命令，这种微指令称为==水平型微指令==。
	- 微指令操作控制字段采用==直接表示法==时，相应的水平型微指令称为==全水平型微指令==。 
	- 微指令操作控制字段采用==编码表示法==时，相应的水平型微指令称为==编码水平型微指令==。
	- 微指令操作控制字段采用==混合表示法==时，相应的水平型微指令称为==混合水平型微指令==。
- 垂直型微指令（性能问题已被淘汰）
	- 更接近机器指令的编码方式
	- 几乎无并行操作能力
