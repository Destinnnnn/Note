## 6.5 异常与中断
### 6.5.1基本概念
 - 中断
	 - [[6.5 异常与中断#6.5.1基本概念|异常]]（内部中断）
		 - 故障（指令执行引起）
			 - 可恢复故障
				 - 例如缺页中断
				 - 回到发生故障的指令继续执行，==断点为当前指令==
			 - 不可恢复故障
				 - 例如未定义指令、越权指令
				 - 由[[1.4 计算机软件#1.4 计算机软件|操作系统]]终止当前进程的执行
		 - 自陷
			 - 程序员通过显式插入特定指令主动触发的异常
			 - 不存在程序断点
			 - ==返回自陷指令的下一条指令执行==
			 - 在单步调试模式下，CPU的陷阱标志位（Trap Flag，TF）被置位。此时每条普通指令执行完毕后，硬件自动触发一次调试自陷异常，将控制权交还给调试器。
		 - 终止
			 - 使CPU无法继续执行的硬件故障，随机出现，与具体指令无关
			 - 例如[[7.1 总线概述#7.1 总线概述|总线]]错误、机器校验错误、异常处理中再次出现异常的双错等
			 - 出现上述情况，当前程序只能终止执行，由==异常服务处理程序==来重启系统。
	 - 外部中断
		 - ==外部设备向CPU发出的中断请求==（如按键、鼠标单击等），请求CPU==暂停当前正在执行的程序==，转去执行为某个外部设备事件服务的中断服务程序，处理完毕后再返回断点继续执行。
		 - 处理外部中断的时机是==一条指令结束后==，指令结束时会查询是否有外部中断请求。
		 - 外部中断是由外部设备随机发起的，与具体指令无关。
	![[Pasted image 20260630223631.png]]
### 6.5.2 异常与中断的处理过程
1. 发生中断事件
2. CPU收到中断请求
	- 发生==故障异常的指令并没有执行完毕==，但必须立即进入中断响应周期
	- 在==指令执行结束时==进入中断响应周期
3. CPU进入中断响应周期进行响应处理
	1. 关中断
	2. 保存断点
	3. 中断识别
	![[Pasted image 20260630224334.png]]
	- ==中断响应周期==内的==操作全部由硬件实现==、并且==不可被打断==。
	- 中断响应周期结束后，CPU从当前[[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理|PC]]中取出==中断服务程序==的第一条指令开始执行，直到中断返回。这部分任务是==软件实现==的。
	- ==整个中断处理过程是硬件和软件协同实现的==。

### 6.5.3 为CPU增加中断处理功能
#### 6.5.3.1 数据通路部分
- 在原来的 [[1.3 计算机硬件#1.3 计算机硬件|CPU]] 内部单总线数据通路基础上，需要增加与中断处理相关的硬件支持。
![[Pasted image 20260702113709.png]]

| 新增部件/信号 | 作用 |
| --- | --- |
| `IE` | 中断使能位，用于控制 CPU 是否允许响应中断。 |
| `STI` | 使 `IE` 置 1，表示==开中断==。 |
| `CLI` | 使 `IE` 清 0，表示==关中断==。 |
| `EPC` | 保存异常或中断处理完成后要返回的断点。 |
| `EPCin` | 允许把内部总线上的断点写入 `EPC`。 |
| `EPCout` | 允许 `EPC` 把保存的断点送到内部总线。 |
| 中断控制逻辑 | 用于中断识别和中断优先级处理。 |
| `ClrInt` | 清除中断请求信号。 |
| `IntAdrout` | 将中断服务程序入口地址送到内部总线。 |

- `IE` 的含义：
	- `IE = 1`：允许中断请求进入后续响应逻辑。
	- `IE = 0`：禁止中断请求进入后续响应逻辑。
- 中断控制逻辑的功能：
	- 接收多个中断源发出的中断请求。
	- 产生送往操作控制器的中断请求信号。
	- 输出当前优先级最高的中断源编号，即==中断号==。
- 图中为了便于理解，使用多路选择器 `MUX` 根据中断号选择固定的中断入口地址。
	- *实际实现时，中断服务程序入口地址并不一定固定，可以通过中断向量表访问存储器来获取。*
- 典型中断响应相关数据流：
	- 关中断：`0 -> IE`
	- 保存断点：[[1.6 计算机的基本工作原理|PC]]` -> EPC`
	- 取中断入口地址：`中断入口地址 -> PC`
	- 中断返回：`EPC -> PC`

#### 6.5.3.2 硬布线控制器的改造
- 若 CPU 采用硬布线控制器，需要在硬件状态序列中增加==中断响应周期==相关状态。
![[Pasted image 20260702113804.png|697]]
- 以支持简单中断功能的三级时序硬布线控制器为例：
	- 取指周期后，若无中断请求，进入原来的指令执行状态。
	- 若有中断请求，进入中断响应周期。
- 中断响应周期中的典型操作：

| 阶段 | 执行操作 | 控制信号 |
| --- | --- | --- |
| 保存断点并关中断 | `0 -> IE`，`PC -> EPC` | `CLI`，`PCout`，`EPCin` |
| 装入中断入口地址 | `当前中断服务程序入口地址 -> PC` | `IntAdrout`，`PCin` |
| 中断返回 | `EPC -> PC`，`1 -> IE` | `EPCout`，`PCin`，`STI`，`ClrInt` |

- 设计思路：
	- 为中断响应增加若干个专门状态。
	- 在这些状态中按节拍产生保存断点、关中断、装入中断入口地址等控制信号。
	- 中断服务程序执行完成后，通过返回指令把 `EPC` 中保存的断点恢复到 `PC`。
- 若支持多级嵌套中断：
	- 中断服务程序执行过程中可能再次响应更高优先级中断。
	- 因此需要合理安排开中断和关中断的位置，以保护现场和恢复现场的完整性。
![[Pasted image 20260702113957.png]]
#### 6.5.3.3 微程序控制器的改造
- 若 CPU 采用微程序控制器，需要同时修改微[[5.2 指令格式#5.2 指令格式|指令格式]]和微地址形成逻辑。

- 微指令格式需要增加与中断处理相关的命令位：
![[Pasted image 20260702114044.png]]

| 新增微命令位 | 作用 |
| --- | --- |
| `EPCin` | 将内部总线内容写入 `EPC`。 |
| `EPCout` | 将 `EPC` 内容送到内部总线。 |
| `STI` | 开中断，使 `IE` 置 1。 |
| `CLI` | 关中断，使 `IE` 清 0。 |
| `IntAdrout` | 输出中断服务程序入口地址。 |
| `ClrInt` | 清除当前中断请求。 |
![[Pasted image 20260702114145.png]]
- 微指令顺序控制字段也需要增加相关判断位，用来决定下一条微指令地址是否转入中断响应微程序。
- 微地址形成逻辑的改造：
	- 正常情况下，按原来的取指微程序、执行微程序顺序运行。
	- 若满足中断响应条件，则下一条微指令转入==中断响应微程序==。
	- 中断响应微程序完成保存断点、关中断和转入中断服务程序入口地址等操作。
- 当中断服务程序最后执行中断返回指令时：
	- 通过微命令 `EPCout`、`PCin` 把断点恢复到 `PC`。
	- 通过 `STI` 恢复开中断。
	- 通过 `ClrInt` 清除对应中断请求。

### 6.5.4 中断服务程序
- 中断服务程序 ISR 是==由软件实现==的中断处理部分。
	- 中断响应周期负责关中断、保存断点和中断识别，这部分由硬件完成。
	- 中断响应周期结束后，CPU 从 `PC` 中的中断服务程序入口地址开始取指执行。
 ![[Pasted image 20260702114224.png]]
- 中断服务程序主要包含 4 个步骤：

| 步骤 | 作用 |
| --- | --- |
| 保护现场 | 保存被中断程序中后续还要使用的寄存器和状态信息。 |
| 中断服务 | 完成中断事件对应的具体处理任务。 |
| 恢复现场 | 按保护现场时的相反顺序恢复寄存器和状态信息。 |
| 中断返回 | 返回断点，使被中断程序继续执行。 |

- 保护现场：
	- 目的是确保中断服务程序执行完毕后，原程序可以正确继续执行。
	- 需要把通用寄存器、专用寄存器以及程序状态字等必要信息保存起来。
	- *通常使用堆栈保存这些现场信息。*
- 中断服务：
	- 针对具体中断事件执行对应操作。
	- 例如外设相关中断处理中，可以完成数据传送、状态检查等任务。
- 恢复现场：
	- 按保护现场的逆序恢复。
	- 只有现场恢复正确，返回断点后原程序才能保持执行前后一致。
- 中断返回：
	- 执行中断返回指令。
	- 将保存的断点送回 `PC`，使 CPU 回到被中断程序继续执行。

- 对于简单的单级中断：
	- 中断响应阶段已经关中断。
	- 中断服务程序执行期间不再响应新的中断。
	- 中断返回前恢复断点并重新开中断。
- 对于多级嵌套中断：
	- 保护现场后应==开中断==，以便中断服务程序运行期间还能响应更高优先级中断。
	- 恢复现场前应==关中断==，保证恢复现场过程的完整性。
