## 8.4 I/O控制方式

### 8.4.1 概述
- I/O 控制方式是指 [[1.3 计算机硬件#1.3 计算机硬件|CPU]] 与 I/O 设备进行信息交互时采用的控制方式。
- 随着计算机和 I/O 设备的发展，I/O 控制方式从简单到复杂、从 CPU 集中控制到分散控制演变。

| 控制方式 | 特点 |
| --- | --- |
| 程序直接控制方式 | CPU 通过程序直接查询或控制 I/O 设备。 |
| [[6.5 异常与中断#6.5 异常与中断|中断]]驱动方式 | I/O 设备完成操作后主动向 CPU 发出中断请求。 |
| 直接存储器存取 [[8.4 I O控制方式#8.4.4 DMA方式|DMA]] 方式 | 数据在 I/O 设备和主存之间直接传送，减少 CPU 参与。 |
| 通道控制方式 | 通道作为专门 I/O 处理器管理 I/O 操作。 |
| I/O 处理机方式 | 进一步由专门处理机管理复杂 I/O 任务。 |
![[Pasted image 20260702151248.png]]
- 重点介绍：
	- 程序直接控制方式
	- 中断驱动方式
	- DMA 方式

### 8.4.2 程序直接控制（查询）方式
- 程序直接控制方式也称查询方式。
- 基本思想：
	- CPU 通过执行一段 I/O 程序完成与 I/O 设备的数据交换。
	- CPU 反复查询 I/O 接口中的状态寄存器，判断设备是否就绪。

- 查询方式分为：

| 类型 | 特点 |
| --- | --- |
| 独占式查询 | CPU 一直查询设备状态，直到设备就绪。 |
| 定时查询 | CPU 每隔一段时间查询一次设备状态。 |
![[Pasted image 20260702151343.png]]
![[Pasted image 20260702151356.png]]
![[Pasted image 20260702151415.png]]

- 独占式查询：
	- CPU 反复读取设备状态。
	- 设备未就绪时，CPU 仍在循环等待。
	- ==会浪费大量 CPU 时间==。
- 定时查询：
	- CPU 在固定时间间隔查询设备。
	- 若查询间隔过长，可能增加设备等待时间。
	- 若查询间隔过短，仍会带来较大开销。
- 查询方式的特点：
	- 实现简单。
	- 硬件开销小。
	- 适用于低速或任务简单的 I/O 设备。
	- CPU 与 I/O 设备之间串行工作，CPU 利用率较低。

### 8.4.3 中断驱动方式
![[Pasted image 20260702151638.png]]

#### 8.4.3.1 中断的基本概念（作用，分类）
- [[6.5 异常与中断#6.5 异常与中断|中断]]驱动方式的基本思想：
	- I/O 设备完成自身操作后，主动向 CPU 发出中断请求。
	- CPU 在等待 I/O 期间可以执行其他任务。
	- 收到中断请求后，CPU 转去处理数据传送或相关服务。

- 相比程序查询方式：
	- 中断驱动方式不需要轮询设备状态。
	- 能提高 CPU 利用率。
	- 中断请求具有更好的实时性。

- 中断的作用：

| 作用 | 说明 |
| --- | --- |
| 提升并行性 | CPU 和 I/O 设备可以并行工作。 |
| 支持程序调试 | 调试器可以利用自陷等机制控制程序执行。 |
| 实现故障与[[6.5 异常与中断#6.5.1基本概念|异常]]处理 | CPU 可转入异常处理程序，提高系统可靠性。 |
| 保障实时处理 | 对外部事件及时响应。 |
| 方便人机交互 | 键盘、鼠标等设备可通过中断通知 CPU。 |
| 实现多任务调度 | 定时器中断支持[[1.4 计算机软件#1.4 计算机软件|操作系统]]进行任务切换。 |
| 支持多处理机系统交互 | 处理器之间可通过中断机制协同。 |
![[Pasted image 20260702151712.png]]
- 中断可分为：
	- 内部异常
	- 外部中断

| 类型 | 示例 |
| --- | --- |
| 故障 Fault | 可恢复或不可恢复的执行故障。 |
| 自陷 Trap | 程序主动触发的异常。 |
| 终止 Abort | 严重硬件故障。 |
| 可屏蔽中断 INTR | 可被中断屏蔽控制影响。 |
| 不可屏蔽中断 NMI | 不能被普通屏蔽位禁止。 |
![[Pasted image 20260702151722.png]]
- 按是否提供[[6.5 异常与中断#6.5.4 中断服务程序|中断服务程序]]入口地址，可分为：
	- 向量中断
	- 非向量中断
	![[Pasted image 20260702151733.png]]
- 按中断服务程序是否允许被新的中断打断，可分为：
	- 单级中断
	- 多重中断
![[Pasted image 20260702151743.png]]
#### 8.4.3.2 中断的基本概念（中断优先级与中断屏蔽）
- [[6.5 异常与中断#6.5 异常与中断|中断]]优先级是 CPU 响应并处理中断请求的先后次序。

| 概念 | 含义 |
| --- | --- |
| 响应优先级 | CPU 对多个中断源的中断请求进行响应的先后次序。 |
| 处理优先级 | 多重中断系统中，中断服务程序之间实际嵌套处理的优先级。 |
![[Pasted image 20260702151802.png]]
- 响应优先级：
	- 通常由硬件设计确定。
	- 一旦确定后较难改变。
- 处理优先级：
	- 可以通过中断屏蔽技术动态调整。
	- 用于控制哪些中断可以打断当前中断服务程序。

- 中断屏蔽：
	- 在中断控制器中包含==中断屏蔽寄存器（IMR)==
		- 为`1`表示屏蔽对应设备发送的中断请求信号
		- 为`0`表示允许对应设备发送中断请求信号
	- 通过==中断屏蔽字==控制某些中断请求是否允许被响应。
	- 可以改变处理中断时的实际优先级关系。
	![[Pasted image 20260702152145.png]]
- 一般规律：
	- 内部[[6.5 异常与中断#6.5.1基本概念|异常]]优先于外部中断。
	- 不可屏蔽中断优先于可屏蔽中断。
	- DMA 中断优先于普通 I/O 设备中断。

#### 8.4.3.3 中断请求
- I/O 设备向 CPU 提出[[6.5 异常与中断#6.5 异常与中断|中断]]请求的方式包括：

| 方式 | 特点 |
| --- | --- |
| 独立请求方式 | 每个中断源有独立请求线，CPU 可直接识别优先级。 |
| 链式请求方式 | 多个中断源共用请求线，通过链式传递识别中断源。 |
| 分组链式请求方式 | 将中断源分组，组内采用链式方式。 |
| 中断控制器方式 | 使用专门中断控制器集中管理中断请求。 |
![[Pasted image 20260702152226.png]]
![[Pasted image 20260702152234.png]]
![[Pasted image 20260702152242.png]]
![[Pasted image 20260702152250.png]]
![[Pasted image 20260702152259.png]]
- 独立请求方式：
	- CPU 可以灵活处理中断优先级。
	- 控制线数量多。
- 链式请求方式：
	- 各中断源通过公共 `INTR` 请求线向 CPU 请求。
	- CPU 通过 `INTA` 应答信号逐级识别中断源。
	- 硬件简单，但优先级固定。
- 中断控制器方式：
	- 以 8259A 为例。
	- 中断控制器内部含中断请求寄存器、优先级判别器、服务寄存器和屏蔽寄存器等部件。
	- CPU 可以通过控制命令设置中断控制器的工作方式。
![[Pasted image 20260702152313.png]]
#### 8.4.3.4 单级中断的处理流程
- 单级[[6.5 异常与中断#6.5 异常与中断|中断]]中，执行[[6.5 异常与中断#6.5.4 中断服务程序|中断服务程序]]时，不再响应其他中断请求。

- 中断响应条件
	1. 相应的中断请求未被屏蔽
	2. 当前没有更高优先级的其他中断请求
	3. 若CPU正在执行中断服务，则中断请求应符合中断嵌套条件
	4. 中断使能位处于使能状态（即开中断状态）
		- ==内部[[6.5 异常与中断#6.5.1基本概念|异常]]和不可屏蔽中断NMI不受此限制
	5. CPU已执行完一条指令的最后一个状态周期，处于可中断时机
		- ==内部异常指令无法执行完毕，所以其中断时机不受此限制

- 单级中断处理流程：
	1. 取指令、执行指令。
	2. 每条指令结束时检查是否有中断请求。
	3. 若有中断请求，进入中断响应阶段。
	4. 硬件自动完成关中断、保存断点、中断识别。
	5. 转入中断服务程序。
	6. 中断服务程序保护现场。
	7. 执行中断服务。
	8. 恢复现场。
	9. 开中断。
	10. 中断返回。
![[Pasted image 20260702152717.png]]
- 中断响应阶段：
	- 由硬件自动完成。
	- 可能需要若干[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]。
	- 主要完成关中断、保存断点和中断识别。
- 中断服务程序：
	- 由软件实现。
	- 包括保护现场、中断服务、恢复现场和中断返回等步骤。
- 单级中断不会发生中断嵌套。

- 中断向量：一般将**中断服务程序的入口地址[[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理|PC]]**和**程序状态字PSW**合称为**中断向量**
	- 某些计算机的中断服务程序需要载入**PSW**才能运行
	- 对于**不需要载入PSW**即可运行中断服务程序的计算机，中断向量就是**中断服务程序的入口地址PC**。
- 中断向量表：由**若干中断向量**构成（中断向量的集合）
	- 通常**存放在主存中**，在[[1.4 计算机软件#1.4 计算机软件|操作系统]]引导过程中初始化。
	- 利用**中断号**对其进行**索引访问**。
- 向量地址：中断向量表中**各表项的地址**，也称为**中断指针**。

#### 8.4.3.5 多重中断的处理流程
![[Pasted image 20260702153236.png]]
- 多重[[6.5 异常与中断#6.5 异常与中断|中断]]允许在执行某个[[6.5 异常与中断#6.5.4 中断服务程序|中断服务程序]]期间，响应更高优先级的中断请求。

- 与单级中断相比，多重中断的关键差异：
	- 保护现场后需要==开中断==，允许更高优先级中断进入。
	- 恢复现场前需要==关中断==，避免恢复现场过程中再次被打断。
- 多重中断处理流程：
	1. 中断响应阶段关中断、保存断点、中断识别。
	2. 进入中断服务程序后保护现场。
	3. 开中断。
	4. 执行中断服务。
	5. 若出现更高优先级中断，可嵌套进入新的中断服务程序。
	6. 当前中断服务完成后关中断。
	7. 恢复现场。
	8. 发送中断结束命令。
	9. 开中断。
	10. 中断返回。

- 中断控制器可通过中断结束命令 EOI 结束当前中断服务。
	- EOI 使中断控制器清除当前中断对应的服务状态。
	- 之后可继续响应新的中断请求。

### 8.4.4 DMA方式
- DMA 是直接存储器存取方式。
- 在 DMA 方式中，数据在 I/O 设备和[[4.1 存储器概述#4.1.3 主存的基本结构|主存]]之间直接传送，传送过程不再完全依赖 CPU。

- DMA 方式引入独立硬件模块：
	- DMA 控制器 DMAC。
- DMA 传送过程：
	1. CPU 向 DMAC 设置 DMA 传送参数，如主存地址、数据块长度、传送方向等。
	2. CPU 启动 I/O 设备和 DMA 传送。
	3. 传送过程中 CPU 可以继续执行其他程序。
	4. I/O 设备需要传送数据时，DMAC 向 CPU 申请[[7.2 总线传输的相关基本原理#7.2.1 总线传输过程和总线事务|总线控制权]]。
	5. DMAC 直接控制 I/O 设备与主存之间的数据传送。
	6. 数据块传送结束后，DMAC 通过[[6.5 异常与中断#6.5 异常与中断|中断]]方式通知 CPU 做后续处理。

- DMA 控制器通常包含：

| 部件 | 作用 |
| --- | --- |
| 地址寄存器 | 保存当前传送的主存地址。 |
| 字计数器 | 保存还需要传送的数据量。 |
| 数据缓冲寄存器 | 暂存传送数据。 |
| 命令/状态寄存器 | 保存控制命令和状态信息。 |
| DMA 控制逻辑 | 产生[[7.1 总线概述#7.1 总线概述|总线]]请求、设备请求响应和传送控制信号。 |

- DMAC 与 CPU 争用主存的常用处理方式：

| 方式 | 特点 |
| --- | --- |
| DMA 独占访问 | DMAC 传送期间独占总线，CPU 暂停访存。 |
| 交替访问 | CPU 和 DMAC 交替使用主存。 |
| 周期挪用 | DMAC 在 CPU 不使用总线或可让出的周期中占用一个存储周期。 |
![[Pasted image 20260702162109.png]]
![[Pasted image 20260702162119.png]]
![[Pasted image 20260702162130.png]]
![[Pasted image 20260702153639.png]]
- DMA 方式与中断驱动方式对比：

| 对比维度 | 中断驱动方式 | DMA 方式 |
| --- | --- | --- |
| 请求控制 | 请求对象是 CPU。 | 请求对象是总线控制权。 |
| 数据传送 | 通常经由 CPU 程序完成。 | 由 DMAC 直接完成。 |
| 适用场景 | 处理零散 I/O 事件。 | 适合大量、高速数据传输。 |

- DMA 并不是完全不需要 CPU：
	- 传送开始前需要 CPU 初始化。
	- 传送结束后通常通过中断通知 CPU。
	- 传送过程中对数据块的传送由 DMAC 接管。
