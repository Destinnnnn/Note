## 6.6 指令流水线

### 6.6.1 概述
- 之前介绍 MIPS 指令执行方法时，采用的是==串行执行方法==：
	- 同一时刻 [[1.3 计算机硬件#1.3 计算机硬件|CPU]] 中只有一条指令在执行。
	- CPU 中各功能部件的使用率不高。
- 为了提高 CPU 内各功能部件的并行性，可以采用==指令流水线技术==。
	- 同一时刻有多条指令在 CPU 中的不同功能部件中并发执行。
	- 现代计算机普遍采用指令流水线技术。
- 指令流水线是一种==时间并行技术==：
	- 将指令处理过程划分为多个阶段。
	- 让不同指令的各个阶段在时间上重叠执行。
	- 使得同一时刻一条流水线上可以有多条指令。

![[Pasted image 20260702114302.png]]

- MIPS32 指令流水线通常划分为 5 个阶段：

| 阶段 | 名称 | 主要工作 |
| --- | --- | --- |
| IF | 取指 | 从指令存储器取出指令。 |
| ID | 译码 | 对指令译码，同时从寄存器堆中读取操作数。 |
| EX | 执行 | 执行运算操作或计算访存地址。 |
| MEM | 访存 | 访问数据存储器。 |
| WB | 写回 | 将结果写回寄存器堆。 |
![[Pasted image 20260702114737.png]]
- ==并不是所有指令都必须经历5个阶段，只能以执行速度最慢的指令作为设计[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]的依据==
- ==单周期CPU的时钟周期由数据通路中的最长路径决定，也就是5个阶段的延迟综合`T_total`== 
![[Pasted image 20260702172558.png]]
- 若每个功能段的最大延迟为 `Tmax`，执行 `n` 条指令、流水线共有 `m` 个功能段：
	- 第一条指令需要经过 `m` 个周期。
	- 后续每增加一条指令，理想情况下只多需要 1 个周期。
	- ==执行 n 条指令需要的时间为 `(m + n - 1)Tmax`==。
- 理想情况下：
	- 指令流水线吞吐率提高。
	- 当流水线充分填满后，==[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|CPI]] 接近 1==。
	- *实际流水线会受冲突、停顿等因素影响。*

### 6.6.2 数据通路
- 流水线数据通路是在单周期 MIPS 处理器数据通路基础上改造得到的。
![[Pasted image 20260702114808.png]]

- 与单周期数据通路相比，流水线数据通路需要增加==流水段寄存器==：

| 流水段寄存器 | 位置          | 作用                                                               |
| ------ | ----------- | ---------------------------------------------------------------- |
| IF/ID  | IF 和 ID 之间  | 保存取指阶段得到的指令等信息。                                                  |
| ID/EX  | ID 和 EX 之间  | 保存译码阶段得到的操作数、立即数和控制信号。                                           |
| EX/MEM | EX 和 MEM 之间 | 保存 [[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理\|ALU]] 运算结果、写寄存器编号和后续访存/写回控制信号。 |
| MEM/WB | MEM 和 WB 之间 | 保存访存结果或 ALU 结果，以及写回阶段控制信号。                                       |
- 各流水段寄存器位数不一定相同
	- IF/ID寄存器：主要存放取出的指令和 PC
	- ID/EX寄存器：需要存放两个源操作数值、符号扩展后的立即数、PC、寄存器编号以及多个控制信号，总位数通常超过 150 位。

- 在流水线中，每条指令进入下一功能段时，需要把以下内容写入==流水段寄存器==：
	- 当前阶段加工后的数据。
	- 后续功能段还要使用的指令相关字段。
	- 后续阶段所需的控制信号。
- 控制信号也需要随指令在流水线中逐级向后传递：
	- ID 阶段产生控制信号。
	- 后续 EX、MEM、WB 阶段按需要使用对应控制信号。
- 即使某条指令不需要某个功能段，也要经过该功能段对应的[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]。
	- 这是为了保证流水线中各条指令按统一节拍向后推进。
	- *例如某些指令不需要 MEM 阶段访存，但仍会经过 MEM 功能段。*
![[Pasted image 20260702115030.png]]
- 尽管某些指令不需要某些功能段，但在这种五级流水线中仍要经过相应阶段。在没有停顿的情况下，一条指令从进入 IF 到完成 WB 需要 5 个时钟周期；时钟周期通常由最慢功能段的组合逻辑延迟加流水段寄存器开销决定。
### 6.6.3 冲突与处理
- 理想流水线中，各阶段延迟相同、没有资源争用和相关性影响。
- 实际指令流水线中，指令之间存在复杂的相互依赖，往往无法达到理想状态。
- 当上述相关性导致流水线出现“阻塞”或“暂停”，下一条指令不能在预期[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]进入流水线时，称为==流水线冲突==。
	- 流水线冲突也称为冒险。

| 冲突类型 | 产生原因 |
| --- | --- |
| 结构冲突 | 多条指令在同一时钟周期争用同一个硬件部件。 |
| 控制冲突 | 分支、跳转等指令改变取指方向，使后续指令可能无法按顺序进入执行阶段。 |
| 数据冲突 | 当前指令需要使用前面指令尚未产生或尚未写回的数据。 |

#### 6.6.3.1 结构冲突与控制冲突
- 结构冲突：
	- 多条指令在同一[[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]争用同一个操作部件。
	- 示例中，计算 [[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理|PC]] + 4、计算分支目标地址、运算器运算等如果争用同一 ALU，就会产生结构冲突。
- 结构冲突的解决方法：
	- ==增加硬件资源==。
	- 例如增加加法器或增加存储器端口，使不同功能段可以并行工作。
	- IF 功能段需要指令存储器，MEM 功能段需要数据存储器；若把指令存储器和数据存储器分离，可避免此类结构冲突。

- 控制冲突：
	- 由分支指令或跳转指令引起。
	- 在分支指令之后进入流水线的后续指令，可能因为分支转移而不应该进入执行阶段。
- 控制冲突的处理：
	- 在执行程序分支转移时，清除流水线中已经取入的错误指令。
	- 示例中，用 `nop` 填充被清除的指令位置，保持 CPU 状态不变。
	- 还可以采用静态分支预测或动态分支预测，减少控制冲突造成的延迟损失。
- 对 MIPS 来说：
	- 空操作指令 `nop` 不改变 CPU 状态。
	- 因此可以在流水线中插入 `nop`，让错误取入的指令不产生实际影响。

#### 6.6.3.2 数据冲突
- 数据冲突是指当前指令需要使用前面指令尚未产生或尚未写回的数据，导致当前指令无法继续执行。

- 数据相关类型：

| 类型 | 涉及操作 | 含义 | 在 MIPS 标准五段流水线中的情况 |
| --- | --- | --- | --- |
| RAW | 写后读 | 后一条指令读取前一条指令将要写入的结果。 | 可能产生数据冲突。 |
| WAR | 读后写 | 后一条指令写入前一条指令需要读取的寄存器。 | 标准五段流水线中通常不会产生。 |
| WAW | 写后写 | 多条指令写同一寄存器。 | 标准五段流水线中通常不会产生。 |

- 在 MIPS 标准五段流水线中，主要关注==RAW 数据冲突==。
	- 前一条指令的结果可能要到 WB 阶段才写回寄存器。
	- 后一条相关指令在 ID 阶段就可能需要读取该寄存器。
	- 因此后续指令可能读到旧值。
- 示例中：
	- 若 `sub` 指令需要读取前面 `and` 指令将写入的寄存器，就存在 RAW 相关。
	- 若两条指令访问的是同一寄存器，但读写顺序不会影响结果，则不一定形成数据冲突。

#### 6.6.3.3 数据冲突解决方案-插入气泡
- RAW 冲突的一种解决方法是==插入气泡==。
	- 气泡在流水线中表现为 `nop`。
	- `nop` 不改变 CPU 状态，只占用流水线时钟周期。
	- 软件方法：在存在RAW冲突的指令间插入一定数量的空操作指令，==需要编译器支持==
	- 硬件方法：插入“气泡”，相当于插入“空操作”
- 插入气泡的基本思想：
	- 让相关指令暂停进入后续阶段。
	- 等前一条指令的结果写回寄存器后，再让后一条指令继续读取正确数据。
![[Pasted image 20260702115732.png]]
![[Pasted image 20260702120013.png]]
- 插入气泡的代价：
	- 会增加执行周期。
	- 会降低流水线性能。
	- 若依赖较多，插入气泡会明显削弱指令流水线的并行效果。
- 课中提到：
	- 可通过 ID 功能段与 EX 功能段、MEM 功能段的 RAW 相关性检测来判断是否需要停顿。
	- 若检测到 RAWHazard，则产生 Stall，使 [[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理|PC]] 和 IF/ID 流水段寄存器暂停更新，并向后续阶段插入空操作。

#### 6.6.3.4 数据冲突解决方案-数据旁路
- RAW 冲突还可以通过==数据旁路==解决。
	- 数据旁路也称为数据转发、重定向。
	- 它不等结果写回寄存器堆，而是把前面流水段中已经产生的结果直接送到后面指令需要使用的位置。
![[Pasted image 20260702120215.png]]

- 数据旁路的典型来源：
	- `EX/MEM` 流水段寄存器中的 ALU 运算结果。
	- `MEM/WB` 流水段寄存器中的访存结果或 ALU 运算结果。
- 数据旁路的典型去向：
	- EX 阶段 [[1.6 计算机的基本工作原理#1.6 计算机的基本工作原理|ALU]] 的输入端。
	- *图中通过增加多路选择器，把旁路数据送入 ALU 输入端。*
- 数据旁路的作用：
	- 减少或消除因 RAW 相关带来的停顿。
	- 提高流水线性能。
- Load-Use 相关：
	- 若一条 `lw` 指令刚从存储器取数，紧随其后的指令立刻使用该数据，会形成==Load-Use 相关==。
	- 图中说明，即使采用数据旁路，Load-Use 相关仍需要在两条相关指令之间插入一个气泡。
	- ![[Pasted image 20260702120325.png]]
	- 气泡可以由硬件实现，也可以由软件插入。
#### 6.6.3.5 超流水线技术和多发射技术
- 为了进一步提高指令执行的并行性，可以采用：
	- ==超流水线技术==
	- ==多发射技术==
- 超流水线技术：
	- 通过增加流水线级数，使每一级逻辑更简单。
	- [[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|时钟周期]]可以进一步缩短。
	- 本质上是把原有功能段继续细分，从而提高流水线频率。
	- ![[Pasted image 20260702120706.png]]
- 多发射技术：
	- 让处理器内部具有多个处理部件。
	- 使每个时钟周期中可以同时对多条指令进行处理。
	- 这些指令可以被分发到不同流水线中并行执行。
	- ![[Pasted image 20260702120722.png]]
- 多发射会引入更多相关性问题：
	- 结构冲突问题更复杂。
	- 数据冲突问题更复杂。
	- 控制冲突问题也需要配合预测和调度处理。
- 多发射分类：

| 类型 | 特点 |
| --- | --- |
| 静态多发射 | 依靠编译器在编译时解决冲突并打包指令。 |
| 动态多发射 | 依靠硬件在执行阶段动态检测冲突并调度指令。 |

-  [[1.7 计算机系统的性能指标#1.7.2 与运算速度相关的性能指标|CPI]] 的比较：

| 处理器类型 | 理想 CPI |
| --- | --- |
| 单周期 CPU | `1` |
| 多周期 CPU | `> 1` |
| 基本流水线 CPU | `1` |
| 超标量流水线 CPU | `< 1` |
